# Video Boost Eval（v2，2026-10-02：加字号与安全区实测）

一支增强片好不好，分三层判：**门槛**（不过就不交付）→ **自动检查**（`eval.py` 跑，规则可机判）→ **人工评分**（机器判不了的审美与判断）。
每一条都能追到用户在迭代里拍过板的决定（右列），改标准先改这里。

```
node audit.mjs runs/<name>                                    # 先量字号与位置（默认 --platform xhs）
python3 eval.py runs/<name>                                   # 默认主题 → runs/<name>/eval.md
python3 eval.py runs/<name> --public public-<theme>            # 别的主题 → eval-<theme>.md
```
依赖：`node build.mjs` 产出的 `public*/manifest.json`（图形时间/文字/镜头）、`voiced.json`、源片与成片。

## A 门槛（任一 FAIL = 不交付）
| # | 检查 | 判定 | 来源 |
|---|---|---|---|
| A1 | 成片时长 = 原片 | 差 ≤ 0.05s | 铁律「只加不改」 |
| A2 | HyperFrames lint | 0 error | 渲染稳定（PRD V3 门槛：无闪屏/错位） |
| A3 | 有语音就有字幕 | 每段 ≥0.3s 发声被字幕覆盖 ≥50% | 字幕红线 |
| A4 | 无语音不出字幕 | 每屏至少 0.15s 落在发声区 | 字幕红线 |
| A5 | 字幕节奏 | <1s 或 >9 字/s 的屏 ≤10%（≤20% 为 WARN）；单屏 ≤12 字 | 竖屏 ≤10 字/屏 + 速度规则 |

## B 内容（自动）
| # | 检查 | 判定 | 来源 |
|---|---|---|---|
| B1 | **卡片不复述口播** | 图形文字（中文二元组+英文词）与同时段字幕的重合率：单个 >60% 记一次，平均 ≤45% 为 PASS | v4 被否：「你是把他说的话又可视化了」 |
| B2 | 口播外的数字有来源 | 数据类图形出现口播没说的数字，必须带「来源/①」；示意界面里的数字只 WARN，人工确认是示例 | 铁律 4 示意≠编造 |
| B3 | 示意界面标「示意」 | cc / folio / resume / checktable 必含「示意」 | 用户同意「可以示意」的前提 |
| B4 | 相邻不同版式 | 间隔 <4s 的相邻图形不能是同一组件 | PRD V3 版面轮换 |
| B5 | 图形密度 | 图形覆盖 30–75% 时长，且 1.5–4 个/分钟 | v4 太密 vs 只留 4–6 个 |
| B6 | 单段 ≤20s | 超 20s 记 WARN（承接型可接受，需说明） | PRD V3 划段 |

## C 运镜（自动）
| # | 检查 | 判定 | 来源 |
|---|---|---|---|
| C1 | 镜头移动落在停顿 | 让位/回全屏的时刻在说话间隙 ±0.15s 内 | 「不在词中间动」 |
| C2 | 不一缩一放 | 全屏 <4s 又让位 = WARN | 运镜规则 |
| C3 | 图形在场人必让位 | 图形 35%/65%/90% 处必须是 split | 不挡脸、不压图 |
| C4 | 硬切放大只给钩子 | ≤1 次，且在前 15% | punch 规则 |
| C6 | 让位先于图形入场 | 镜头开始让位（t−0.4s）不晚于图形入场 | 「split 的落位要早于图形入场」 |
| C5 | 人单独在场占比 | 25–60%（低于 25% 说明图形太满） | 「人是内容」 |

## T / S 字号与安全区（自动，先跑 `node audit.mjs runs/<name> [--platform xhs]`，它在无头 Chrome 里把时间线拨到每个图形的中段和末段，量出每段文字实际渲染的字号与位置）
| # | 检查 | 判定 | 来源 |
|---|---|---|---|
| T1 | 字号都在阶梯上 | 只允许 22/28/36/54/96/140 | references/typography.md §1 |
| T2 | 每个图形 ≤3 档阅读字号 | micro、display/hero 另计；4 档 WARN，5 档以上 FAIL | 「字整体偏大、层级乱」的纠偏 |
| T3 | 没有小于 22px 的文字 | 动画中途的缩放不算 | 手机可读下限 |
| T4 | 字幕是最大的阅读文字 | 比字幕大的元素每个图形最多 1 个 | BBC 字幕规范 |
| T5 | micro 只给来源、标签、缩略卡片 | 其余 micro 字数 ≤25% | 层级规则 |
| S1 | 文字避开平台界面 | 按 `--platform` 的上/下/右留白，10px 容差；界面骨架（进度标、logo、字幕）也查 | 各平台安全区 |

## R 字幕（对照用户《【Eval】字幕增强》的红线，取能用程序判断的条目）
源片自带烧录字幕、我们的字幕关闭时，这一组只查「不出现双字幕」（TS-11）。
| # | 检查 | 判定 |
|---|---|---|
| R0 | 不出现双字幕（TS-11） | 源片有字幕时我们的字幕必须关闭 |
| R11 | 单屏 ≤7 秒（R-11） | 超过即 FAIL |
| R12 | 字幕不晚于语音出现（R-12） | 任一屏晚于第一个字的发声即 FAIL |
| R13 | 起止与语音偏差 ≤200ms（R-13） | ≥95% 的屏达标为 PASS，≥85% 为 WARN |
| R15 | 单屏 1 行（R-15） | 实测胶囊行数 |
| R16 | 字号 3–4% 画面高（R-16，9:16） | 实测 |
| R21 | 居中、不出界、底边距 15–20%（R-19/20/21） | 实测 |
| R24 | 字幕不压图形文字（R-24） | 实测：字幕框和图形文字框不重叠 |
| R30 | 数字与单位、专名不被拆到两屏（R-27/28/30） | 程序判断 |
| R35 | 不以挂空的功能词结尾（R-35） | 只给 WARN 清单，句末语气词「…的」人工放行 |

**自动分** = B+C+T+S+R 各项 PASS=1 / WARN=0.5 / FAIL=0 的平均 ×100。

## H 人工评分（1–5，写到秒）
| # | 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|---|
| H1 | **静音测试**：关掉声音和字幕，每张图多给了什么 | 图上就是字幕的缩写 | 一半图有新信息（结构/对比），一半在复述 | 每张图都给了耳朵拿不到的东西：机制、真实界面、真实数据 |
| H2 | **演示力**：口播提到的操作/产出物被演出来 | 用文字卡描述操作 | 有界面但是灰条占位 | 真实界面逐步演示到产出物（指令→工具→结果→来源） |
| H3 | **事实诚实** | 有编造数字或冒充真实的假数据 | 数字有来源但口径没说清 | 数字可点开核对、口径不同写区间；示意明确标注且不带热度/点赞假数 |
| H4 | **品牌一致** | 出现主题外颜色/字体，强调色满屏 | 色板对但强调色用了两处以上 | 只用主题角色色，强调色一屏一处，字体/圆角/阴影全按规范 |
| H5 | **节奏与留白** | 图一直在、人一直小；或该图解处没图 | 图与人切换基本合理，偶有挤 | 人讲观点时在全屏、图讲信息时让位，跟着论证走，有呼吸 |
| H6 | **可读性** | 字压进字幕带/挡脸/对比不足 | 个别屏字小或对比偏弱 | 所有字在手机上一眼可读，字幕始终清楚 |

**总分** = 门槛通过 ×（自动分 × 40% + 人工均分/5 × 60%）。≥85 可直接发；70–85 修 WARN 后发；<70 返工。

## 自动检查的已知盲区（靠人工补）
- B1 分不清「枚举型」与「复述型」：6 项并列列表天然和原话重合，WARN 后人工判是否耳朵接得住。
- 几何类：文字出界、进安全区已由 audit.mjs + S1 自动判；元素压脸、图形之间互相遮挡仍靠 review.sh 联系表人工看。
- 不检查颜色是否越出主题（H4 人工）；后续可扫 index.html 里的色值是否都来自 theme.json。
