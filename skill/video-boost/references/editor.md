# 剪辑师视角：先想「这里切到什么画面」，再想用哪个组件

用户 10-02 的反馈：盲测片「可视化没有之前好了」。原因是规则写成了「内容形状 → 组件」，结果大部分图形变成表格和文字卡，又回到了「把他说的话再可视化一遍」。之前做得好的几版（真实工具界面一步步演示、简历被改写、示意线条真的裂开）都是先想**剪辑师会切到什么画面**。本文件把这个视角写成规则。§1–§4 是硬规则，§5 是审片清单。

## 1. 剪辑台本：写 beats.mjs 之前先写 `runs/<name>/cut.md`

逐段填这张表，一行一个打算放图形的段落：

| 时间 | 口播在讲什么（一句话） | 功能 | 剪辑师会切到的画面 | 素材等级 | 为什么不用更高一级 |
|---|---|---|---|---|---|

- **功能**只能填三种：**解释**（耳朵接不住的结构）、**证明**（让观众相信这件事是真的）、**重置注意力**（太久没有视觉变化）。三种都填不上，这一段就不加图，回到全屏。
- **素材等级**（从高到低，先往高处找）：
  1. **真实素材**：新闻网页截图、官网/报告页面、真实照片、产品真实界面。工具：`node grab.mjs <网址> runs/<name>/assets/x.png --find "关键句"`（截图并给出关键句的位置，直接填进 `photo` 组件的 marks）；`python3 commons.py "<英文关键词>" runs/<name>/assets`（Wikimedia Commons 公开授权图，自动记授权和作者）。
  2. **演示**：把口播描述的操作或产出物演出来（`cc` / `folio` / `resume` / `checktable` 等示意界面）。
  3. **数据图**：数字要有对比或变化才画（`stat` / `trend` / `share` / `gauge` …）。
  4. **文字卡**：只给真的没有画面可演的抽象概念（`definition` / `notthis` / `chain` / `grid` / `cases` …）。
- 选第 3、4 级时，「为什么不用更高一级」那一列必须写具体理由。例如「这个说法没有公开出处，截不到页面」可以；「方便」不行。
- **口播提到一个真实存在的东西**（一则新闻、一份报告、一家公司、一个产品、一个地方、一类人群），先试第 1 级。例如口播说「某项运动最近很火」，就截官方媒体发布的参与人数报道，在那个数字上划荧光笔，而不是写一张大数字文字卡。
- 一个画面只讲一件事。复杂内容按口播顺序逐项进入，不一次性摆出整张表。出现「三张空格子等着填」的画面，说明这段应该拆开，或者换成真实素材。

## 2. 节奏

- **图形段内**：同一个画面状态最多停 6–8 秒，之后要有新元素进入、镜头滚动，或者划重点。一张图整体停 5–6 秒左右最好读，再长就要拆。（Eval E2 自动检查）
- **全屏段**：人单独出镜是让观众喘气，也是建立信任。但连续超过约 30 秒没有任何视觉变化（没有图形、没有推近），就要找一处补一个（慢推、或者一个第 1 级素材）。（Eval E3）
- **卡点**：图形的入点对准关键词的第一个字（用 `t('…原话…')`）；出点不要压在句尾最后一个字上，要等这句说完。
- **不是每句都要配图**：低负荷的观点、情绪、过渡保持全屏。全片图形 4–6 个就够，宁少勿滥。

## 3. 强调手段，不止加图

| 手段 | 什么时候用 | 别滥用 |
|---|---|---|
| 推近 `push` | 结构转折、关键判断 | 全片 3–4 处以内 |
| 硬切放大 `punch` | 只给开头钩子 | ≤1 次 |
| 荧光笔 / 圈注（`photo` 的 marks、`annot`） | 证据里的那个数字或那句话 | 每个画面 ≤2 处 |
| 回到全屏 | 观点、情绪、金句 | 不要为了「有东西」硬塞图 |

## 4. 真实素材的来源与版权

- 新闻、网页截图作为评论里的佐证，画面上必须写**来源名 + 日期**（`credit`），浏览器地址栏写域名（`url`）。截之前先读原文，核对数字确实在页面上。
- 公开授权图只用 CC0 / CC BY / CC BY-SA / 公有领域；`credit` 用 `commons.json` 里的原文（作者 · 授权 · 来源）。
- 不截需要登录的页面、付费墙后的内容、个人社交账号。不用图库水印图。
- 截图会自动去掉浮动广告、吸顶栏和 Cookie 条；还有遮挡的话，用 `--hide "<选择器>"` 去掉。

## 5. 剪辑师审片（渲染草稿之后、正式渲染之前）

派一个**独立子 agent**，只给它 `review.sh` 拼出的关键帧图和 `cut.md`，让它按下面的清单逐段给出「过 / 打回 + 理由」：

1. 这个画面关掉声音还成立吗？给了观众耳朵拿不到的东西吗？
2. 能不能换成更高一级的素材？（真实网页、照片、真实界面）
3. 有没有一屏塞了好几个想法？有没有空格子、大片留白、整张表一次性摆出来？
4. 一眼能看出该看哪里吗？（一个焦点：荧光笔、圈注，或者唯一的大数字）
5. 有没有业余感：装饰性的图、每句都有特效、字墙、挡脸、压字幕。
6. 全片节奏：哪里太久没变化，哪里太挤。

被打回的段落改完再拼图复审，审过了再出正式版。

## 依据
- 每个画面先问它的作用（解释 / 证明 / 重置注意力），装饰性的删；约两句话（8–10 秒）没有视觉变化就补一个；切点不压句尾：[jupitrr](https://jupitrr.com/how-to/edit-talking-head-videos)
- B-roll 要演出口播说的那个东西：[InsideTheEdit](https://www.insidetheedit.com/blog/pacing-in-video-editing)
- 视觉先行、用视觉证据支撑观点（Johnny Harris）：[Medium](https://medium.com/@LMK_writing/how-johnny-harris-mastered-visual-storytelling-on-youtube-343ddf9160ec)
- MKBHD 写稿时就标好对镜头和盖 B-roll；人脸与 B-roll 约 20–40 秒交替：[PandaStudio](https://www.writepanda.ai/blog/mkbhd-editing-style-measured/)
- 单个画面停 5–6 秒；新手最常见的错误是 10 秒塞 4 个想法：[cliptude](https://cliptude.com/vox-style-animation/)
- 推近整条只留给结构转折（Ali Abdaal Shorts）：[PandaStudio](https://www.writepanda.ai/blog/how-to-edit-shorts-like-ali-abdaal/)
- 公开授权素材署名格式（标题 / 作者 / 来源 / 授权）：[Wikimedia Commons](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia/licenses)、[Creative Commons](https://wiki.creativecommons.org/wiki/Recommended_practices_for_attribution)
- 来源多为二手整理文章，数值是经验值；「逐步揭示优于整表」是归纳，没有直接出处。
