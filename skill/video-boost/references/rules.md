# 拆分与选型规则（自包含版）

写 beats.mjs 时用的全部判断规则都在这里，不依赖任何外部文档。

## 1. 负荷类型：哪里值得放图形

逐句问：观众只靠耳朵听，这里会不会听不懂、掉线、记不住？会，就标一个负荷类型。

| 代号 | 类型 | 触发信号 |
|---|---|---|
| NUM | 数字与数据 | 具体数值、百分比、金额、倍数、变化幅度 |
| ENU | 层级与枚举 | 「有三点」「分为几类」、并列多项 |
| SEQ | 时序与流程 | 先…再…最后、因果链、步骤、时间线 |
| TRM | 术语与专名 | 新概念、专有名词、下定义 |
| CMP | 对比 | A vs B、前后变化、新旧方案、优劣 |
| ABS | 抽象机制 | 看不见摸不着的机制、模型、底层逻辑 |

- **不放图形**：过渡句、寒暄、口头禅、情绪表达、重复强调、观点类结论（这些时候人就是内容，回全屏）。
- **复合类型**：一个片段最多标两类，记作「主类 + 次类」，比如 `CMP + NUM`。主类决定用什么版式，次类作为元素叠在这个版式里，不另起一套版式。判出三类以上，说明这段太满，要拆段。
- **划段**：从负荷点向两边延到自然停顿，单段一般 4–12s，不超过 20s。例外是「承接型」：同一张图在下一段里继续点亮、续填（同一条时间轴往下走、同一张简历继续命中关键词），可以超过 20s，交付时说明。
- **版式轮换**：相邻两段不能用同一种版式。上面的承接型不算重复。
- **示意界面优先**：口播在描述一个操作或产出物（用某工具做了什么、改简历、做作品集）时，不走上表，直接用示意界面组件（cc / folio / resume / checktable）把它演出来。

## 2. 模板选型与入场顺序

先按数据形状选模板，再按下表固定的顺序入场。入场顺序是这些模板的核心：顺序错了，观众就读不懂。

| 代码 | 什么时候用 | 入场顺序 | 本库组件 |
|---|---|---|---|
| NUM-01 数据大牌 | 只有 1 个数，没有可比对象 | 小标签（先给语境）→ 数值 → 下划线 → 出处。**数值绝不能第一个出现** | `stat` |
| NUM-02 计数器 | 起点和终点都有，且变化明显 | 底槽 → 数字和进度弧同步推进 → 停 0.3s 后出标签 | — |
| NUM-03 变化率 | 1 个差值或变化率，必须有基准期 | 箭头（先给方向）→ 数值 → 基准期 | — |
| NUM-04 参照物换算 | 数太抽象，需要挂到熟悉的东西上 | 原始数值 → ≈ → 参照物 → 参照物的可数图形。**参照物必须晚于原数** | — |
| NUM-05 占比 | 各部分加起来是整体 | 整体轮廓 → 各部分按口播顺序长出 → 标签。**整体必须先于部分** | `share`、`checktable`（减法版） |
| ENU-01 卡片堆叠 | 3–4 项，口播用了序数词逐个引出 | 第 n 张升入并高亮 → 第 n−1 张上推变暗 → 讲完全部同屏 | — |
| ENU-02 网格清单 | 4–6 项短词，一口气列举，没有序数词 | **全部空框同时出现**（先给总数）→ 按口播逐格点亮 | `grid`、`resume` 的关键词区 |
| ENU-03 逐行高亮 | 5–8 项，或每项超过一行 | 全部行暗着出现 → 当前行高亮 → 讲完转暗，下一行接上。任何时刻只亮一行 | `lines` |
| ENU-04 层级 / 阶梯 | 有上下级或递减关系 | 树状：根 → 连线 → 子节点；阶梯：逐级出现 | `ladder` |
| SEQ-01 时间轴 | 3–6 个带日期的节点 | 整条轴线 → 进度推进 → 到达的节点点亮 | `ctxline` |
| SEQ-03 流程图 / 推导链 | 3–5 步，前一步的产出是后一步的输入 | 起点方块 → 箭头 → 下一方块。**箭头晚于前一个、早于后一个**；终点换色描边 | `chain` |
| TRM-01 定义卡 | 首次出现并且在下定义 | 术语大字 → **停 0.5s** → 分隔线 → 释义 | `definition` |
| TRM-03 反例对照 | 先否定一个常见说法 | 错误的一侧先立住 → 划掉 → 正确的一侧 | `notthis` |
| CMP-01 分栏 | 正好 2 个对象，口播明确表态 | 旧/差一侧 → 中缝劈下 → 新/好一侧。中缝必须在两侧之间出现 | `split` |
| ABS-01 物理隐喻 | 抽象概念首次出现，能抽出一个动作 | 静态承载物先在场 → 动作发生 → 标注结果 | `gauge` |
| ABS / 机制 | 两个量此消彼长 | 坐标轴 → A 线画出 → B 线画出 → 间距标注 | `trend` |
| 事实 / 占位 | 「X 一定会去做 Y」类判断 | 赛道行随口播出现 → 真实产品逐个落位 → 危险度色带 | `occupied` |
| STR-01 漏斗 | 3–5 级，每级都有通过率 | 最宽一层 → 逐层往下 → 每层标通过率 | — |
| STR-03 冰山 | 「看得见的 vs 实际上的」 | 水面线 → 水上部分 → **水下部分最后揭开** | — |

表里标「—」的模板，本库还没有对应组件。真遇到时，按入场顺序新写一个组件，加进 components.mjs。

## 3. 时间
- 元素在关键词**被说出的那一刻**出现，用 `t('…原话…')` 取时间。
- **结论类元素**（gap 标注、结果标签、「只有这一行值钱」这种）出现后至少要在屏上停 1.5s。如果下一张图来得太快，就把结论提前到上一句出现。
- 指令类文字逐字打出，dur 约等于这句话的时长。

## 4. 论证结构 → 小标题（先结构，后标题）
小标题不能一段一段地单独起名，必须先**通读全文，理出整支片子的结构**，标题从结构里自然长出来。

**第一步：写 `runs/<name>/structure.md`**（三行就够）
1. **论点**：一句话，全片要证明什么。
2. **结构类型**：这几段之间是什么关系。常见的有：
   - **路径**：按做事的先后顺序走，比如求职：盘点自己 → 找方向 → 改简历 → 过面试。
   - **框架**：一步步推下来，比如公式 → 拆分 → 条件 → 清单 → 方向 → 检验。
   - **并列**：几条平行的理由或方法。
   - **问题 → 原因 → 解法**。
   - **对比**：前后对比，或者正反对比。
3. **每段的角色 + 结论**：这一段在结构里起什么作用（角色词），以及它说出的结论。

**第二步：小标题 = 角色词 · 结论**
- **角色词**取自上面的结构，2 个字为宜（盘点 / 方向 / 简历 / 面试，公式 / 拆分 / 条件 / 清单 / 方向 / 检验）。观众只看角色词，就能看出这支片子是一条路径还是一套框架。
- **结论**用口播里的说法写成动宾或判断句，不写话题名词，不加原话没有的观点。
- 全长 ≤12 字（英文字母算半个），太长会挤到右上角的 logo。
- **自检**：把所有小标题连起来读，应该就是 structure.md 的论证。读不通，说明结构没理对，回到第一步。
- 开场段和回顾段在进度标上不显示名字（显示「N 点」「N 点 · 讲完」）。

**样例**（大厂人转型 AI，路径型）：盘点 · 用 AI 做出过什么 → 方向 · 卖你的行业经验 → 简历 · 改用 AI 叙事 → 面试 · 证明离不开 AI。
**样例**（AI 应用值不值钱，框架型）：公式 · 做一道减法 → 拆分 · 补丁会没，结构会涨 → 条件 · 攒得比模型快 → 清单 · 六种结构由强到弱 → 方向 · 越垂直越安全 → 检验 · 升级那天的反应。

## 5. 机位密度：信息越密，人越小
| 布局 | 人 | 图形区 | 什么时候用 |
|---|---|---|---|
| `split` | 62%，贴底居中 | 550px | 普通图形：机制图、推导链、时间轴、作品集页 |
| `dense` | 50%，贴底居中 | 760px（`dense: true` 的图形自动用大号版式） | **信息密**：表格 ≥8 行、清单 ≥6 项、示意界面会话/报告、简历这类要读的界面 |

- 人始终贴底居中、脸在字幕带上方。**不缩到角落**（角落画中画已被否）。
- 相邻两个图形一个 split、一个 dense 时，在两段之间的停顿里切换，不回全屏。
